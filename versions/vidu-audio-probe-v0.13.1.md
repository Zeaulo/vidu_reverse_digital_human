# 当前网页实时通话的参考音频测试

测试时间：2026-10-31。使用用户授权的本地 MP3，从第 60 秒截取 10 秒，转换为 16 kHz、单声道 PCM。测试使用用户此前提供的角色和独立临时 Vidu 会话；不复用直播中的会话。测试后挂断测试会话并关闭测试浏览器。

## 测试方式

`test/probe_vidu_audio.py` 仅在显式指定 `--execute` 时连接 Vidu。`test/vidu_audio_probe_init.js` 在测试页将该音频作为麦克风输入，并仅记录 WebSocket 类型及 payload 字段名称、RTC 音频统计与非敏感状态；未向 WebSocket 构造或发送未经确认的音频消息。脚本不保存手机号、Cookie、令牌和信令正文。

## 第二轮结果

- 测试前后通话均为 connected；官网发生 1 次音频设备请求。
- 被 RTC 发送器使用的音频轨道与测试注入轨道一致；播放期间输入 RMS 峰值约 0.08794，发送统计从 0 增至 82,658 字节、534 个数据包，发送音频累计能量从 0 增至约 0.298。
- 接收端音频字节从 29,216 增至 115,681；远端接收轨道录音在 `test/artifacts/vidu_audio_probe_response.webm`，转码 MP3 时 ffmpeg 报告一次 Opus 包头解析错误，生成文件约 24.24 秒，部分音频可能受损。
- 本机 faster-whisper base 对转码后音频识别到一段简短安慰性语音，开始约为录音第 12.7 秒；本次未识别到跟唱的可靠证据。语音识别可能误判，不能凭它单独证明 Vidu 的理解内容或因果关系。
- 本次采样的业务 WebSocket 帧只有初始化 type 1/2 和媒体状态 type 11，未观察到歌曲音频通过 WebSocket 发送。采样结果不证明平台不存在其他未公开音频接口。

## 结论与边界

本次实测支持：当前网页实时通话能将所提供歌曲片段作为 RTC 麦克风输入发送，且存在远端音频流。它不证明 Vidu 以 WebSocket 接受音频，也不证明数字人能够跟唱、模仿旋律或保持歌曲时长。测试结果限于本次会话、该片段与当时的服务状态；后续如需产品化，需单独设计音频入口、授权和可中止的直播调度。
